# nanmo-wakaran：前提なしで Haiku に読ませて、説明を直す

Haiku は、会話の経緯もプロジェクトの前提も知らない読み手として使う。
Haiku が読み違えた箇所・理解できなかった箇所が、説明に足りない情報の手がかりになる。
読み違いを見つけて直すのは、このスキルを使っている側（メインのモデル）の仕事。

## 手順

1. **対象の文を決める**
   利用者が指した説明。指していなければ、直前の自分の説明。
   文はそのまま抜き出す。会話の経緯・前提・補足は足さない。

2. **Haiku に読ませる**
   Agent ツールで、`subagent_type` を `nanmo-wakaran:nanmo-wakaran`、`model` を `haiku` にして呼ぶ。
   依頼の文（prompt）は、手順1の文だけにする。前置きも付けない。

3. **理解と意図を比べる**
   返ってきた「どう理解したか」を、自分が伝えたかったことと1点ずつ比べ、次を書き出す（利用者には出さない）。
   - 違う意味に読まれた点
   - 理解されなかった言葉
   - 読み取れなかった結論・頼みごと・決まったこと

4. **足りない情報をまとめる**
   ずれの原因になった情報を挙げる。たとえば、今どうなっているか・言葉の意味・何のためか・何を頼んでいるか。

5. **書き直す**
   - 1文目に、利用者が聞いていることへの答えを書く
   - 手順4の情報を、必要な分だけ足す。足した分だけ、要らない文を削る
   - 新しい言葉を持ち込まない

6. **もう一度読ませる**
   書き直した文だけを、手順2と同じく Haiku に読ませる。
   意図どおりに理解されたら出す。ずれが残れば手順3から直す。読ませるのは2回までにする。

7. **出し直す**
   書き直した説明だけを利用者に出す。手順3・4の書き出しは、聞かれたら出す。
